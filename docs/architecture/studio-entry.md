# Starting a garden plan

A new visitor sees one primary action: Start with a 4 × 8 bed. The planner is constructed only when the visitor starts setup, chooses mapping or backup/account recovery, or selects an example. Merely viewing this screen does not create a default demo save.

The existing four-step setup handles dimensions, plant choices, arrangement and saving. The map action opens Advanced garden tools; backup and account buttons lead to the existing recovery controls. Example links open the gallery, and selecting a card mounts the planner before dispatching the garden selection.

An existing browser draft bypasses the welcome screen. Only the currently signed-in owner's key is checked; signed-out visitors use the existing local planner key. The entry screen does not parse, migrate, delete or overwrite draft contents. Existing fragment links also bypass it, preserving crop and account-garden handoffs. Browser storage failures still allow entry, with the planner's storage-status and backup handling retained.

This does not merge unsaved gardens across origins or prove real account synchronization. Data and module imports may still load before entry; deferred construction is not a claim that all resources are lazy-loaded.
